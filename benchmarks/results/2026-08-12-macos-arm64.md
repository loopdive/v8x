# V8, QuickJS, and js2wasm — macOS arm64, 2026-08-12

Medians of five fresh processes per engine. Each footprint process retains 100
live instances; the steady slope is measured from instance 10 through instance
100. Every absolute result is accompanied by a ratio to real V8.

## Footprint and startup

Lower is better. Relative columns divide each absolute result by V8, so V8 is
1.000×.

| Metric | V8 | QuickJS | QuickJS / V8 | js2wasm | js2wasm / V8 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Combined linked payload | 39.104 MiB | 4.493 MiB | 0.115× | 2.358 MiB | 0.060× |
| One live instance RSS (shared init included) | 7.875 MiB | 9.172 MiB | 1.165× | 1.594 MiB | 0.202× |
| Steady RSS per additional instance | 1.030 MiB | 1.619 MiB | 1.572× | 40.9 KiB | 0.039× |
| Steady virtual address space per instance | 517.394 MiB | 4.478 MiB | 0.009× | 4.063 GiB | 8.040× |
| Steady module/isolate creation time | 314 µs | 3,095 µs | 9.857× | 43 µs | 0.137× |

The linked payload is a stripped benchmark executable. The js2wasm number
counts its 1,784,216-byte compiler-free runtime plus one shared 688,080-byte
`.cwasm` program artifact; it does not count the compiler or Cranelift. V8 was
41,003,072 bytes and QuickJS was 4,711,592 bytes.

The virtual-address result is the main counterweight to js2wasm's RSS result.
Wasmtime does not commit 4.063 GiB of physical memory per instance, but its
current WasmGC configuration reserves that address range. Real V8 also reserves
about 517 MiB per isolate here, while QuickJS reserves about 4.5 MiB.

## Warm execution speed

Absolute columns are elapsed time, so lower is better. Relative columns report
throughput versus V8, so higher is faster and V8 is 1.000×.

| Warm workload | V8 | QuickJS | QuickJS speed vs V8 | js2wasm | js2wasm speed vs V8 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Export-call boundary (200,000 calls) | 31.039 ns/call | 44.229 ns/call | 0.702× | 15.030 ns/call | 2.065× |
| Numeric kernel (10,000,000 loop iterations) | 4.107 ns/iteration | 17.707 ns/iteration | 0.232× | 9.489 ns/iteration | 0.433× |

On this narrow numeric kernel, js2wasm delivers 43.3% of V8's throughput and
about 1.87× QuickJS's throughput. The trivial typed Wasmtime export boundary is
faster than the V8 and v8x/QuickJS call paths, but this row does not compare a
Deno op: each engine uses its native host API. The kernel makes the one-time
export lookup negligible but remains a microbenchmark, not application or HTTP
throughput.
